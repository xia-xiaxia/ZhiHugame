# EventManager 重构说明

## 重构概述
将原本臃肿的 `EventManager.cs`（500+ 行）拆分成职责清晰的多个类，遵循**单一职责原则**。

---

## 新架构结构

```
EventManager (协调器，100行)
    ├── EventDatabase (数据层，150行)
    │   └── 负责：事件加载、查询、ID去重
    │
    ├── EventSelector (抽取层，160行)
    │   └── 负责：事件抽取逻辑、白名单管理、延时事件
    │
    └── OptionEffectHandler (效果层，140行)
        └── 负责：选项效果执行、数值变化、BUFF、结局判定
```

---

## 各类详细职责

### 1. **EventDatabase.cs** - 事件数据库
**职责：**
- 从多个 JSON 文件加载事件
- 自动处理 ID 冲突（通过 `文件名_ID` 前缀）
- 提供事件查询接口
- 管理随机事件池（不重复抽取）

**核心方法：**
```csharp
LoadEvents()                    // 加载所有事件
GetEvent(string globalId)       // 根据ID获取事件
GetRandomEventUnique()          // 随机抽取不重复事件
ResetPool()                     // 重置事件池（重新开始游戏）
```

**特性：**
- ✅ 解决了多文件 ID 冲突问题
- ✅ 自动给事件 ID 加前缀（`文件名_原始ID`）
- ✅ 自动处理选项中的 `nextEventId` 前缀

---

### 2. **EventSelector.cs** - 事件选择器
**职责：**
- 决定下一个应该触发的事件
- 管理事件抽取优先级（延时 > 强制 > 随机）
- 跟踪已使用的事件（防重复）
- 管理延时事件队列

**核心方法：**
```csharp
DetermineNextEventId(int currentYear)   // 决定下一个事件ID
SetNextEventId(string eventId)          // 设置强制后继事件
AddDelayedEvent(int year, string id)    // 添加延时事件
MarkEventUsed(string eventId)           // 标记事件已使用
Reset()                                 // 重置所有状态
```

**抽取优先级：**
1. **延时事件** - 到期的定时触发事件
2. **强制后继** - 选项指定的下一个事件
3. **随机抽取** - 从未使用的事件中随机选择

---

### 3. **OptionEffectHandler.cs** - 选项效果处理器
**职责：**
- 执行选项的各种效果
- 处理特殊结局触发
- 应用数值变化
- 激活 BUFF
- 处理后继事件

**核心方法：**
```csharp
ApplyOption(Option opt, int year)       // 应用选项效果
TryTriggerSpecialEnding(Option opt)     // 检查特殊结局
ApplyStatChanges(Option opt)            // 应用数值变化
HandleBuffActivation(Option opt)        // 处理BUFF激活
HandleNextEvent(Option opt, int year)   // 处理后继事件
```

**处理流程：**
1. 检查特殊结局（999骑马、666盗匪）
2. 应用五维数值变化
3. 激活 BUFF
4. 处理立即/延时后继事件
5. 更新 UI

---

### 4. **EventManager.cs** - 事件管理器（重构版）
**职责：**
- 作为协调器整合各个子系统
- 提供统一的对外接口
- 保持与旧代码的兼容性

**核心方法：**
```csharp
GetEvent(string id)              // 获取事件（代理到 EventDatabase）
DetermineNextEventId()           // 决定下一个事件（代理到 EventSelector）
ApplyOption(Option opt, int year) // 应用选项（代理到 OptionEffectHandler）
ReloadAllEventsForRestart()      // 重新开始游戏
```

---

## 重构优势

### ✅ **代码结构清晰**
- 每个类只负责一件事
- 500+ 行代码拆分成 4 个 100-150 行的类
- 易于理解和维护

### ✅ **易于测试**
- 各个模块可以独立测试
- 不需要初始化整个游戏系统

### ✅ **易于扩展**
- 添加新的选项效果：只需修改 `OptionEffectHandler`
- 修改抽取逻辑：只需修改 `EventSelector`
- 更换数据源：只需修改 `EventDatabase`

### ✅ **降低耦合**
- 各模块通过单例访问，不直接依赖
- 可以轻松替换某个模块的实现

### ✅ **保持兼容**
- 旧代码调用 `EventManager` 的方法仍然有效
- 无需修改 `GameControl`、`UIManager` 等其他类

## 使用示例

### 获取下一个事件
```csharp
// 旧代码（仍然可用）
string nextId = EventManager.Instance.DetermineNextEventId();
GameEvent evt = EventManager.Instance.GetEvent(nextId);

// 新代码（更清晰）
string nextId = EventSelector.Instance.DetermineNextEventId(currentYear);
GameEvent evt = EventDatabase.Instance.GetEvent(nextId);
```

### 应用选项效果
```csharp
// 旧代码和新代码都一样
EventManager.Instance.ApplyOption(selectedOption, currentYear);
```

### 重新开始游戏
```csharp
EventManager.Instance.ReloadAllEventsForRestart();
// 内部会调用：
// - EventSelector.Instance.Reset()
// - EventDatabase.Instance.LoadEvents()
```

## 注意事项

### ⚠️ **场景设置**
需要在场景中添加 3 个新的 GameObject：
1. `EventSelector`（挂载 EventSelector.cs）
2. `OptionEffectHandler`（挂载 OptionEffectHandler.cs，并绑定 `stats`）
3. `EventDatabase`（已存在，确保在 Inspector 中绑定 `eventJsons`）

### ⚠️ **依赖关系**
```
EventManager ──┐
               ├──> EventDatabase
               ├──> EventSelector
               └──> OptionEffectHandler ──> BuffManager
                                        └──> GameControl
```

### ⚠️ **初始化顺序**
确保以下顺序初始化：
1. EventDatabase（Awake 中加载事件）
2. EventSelector（Awake 中初始化）
3. OptionEffectHandler（Awake 中初始化）
4. EventManager（Awake 中初始化）

## 总结

这次重构将复杂的 `EventManager` 拆分成了职责清晰的 4 个类：
- **EventDatabase**：专注数据管理
- **EventSelector**：专注抽取逻辑
- **OptionEffectHandler**：专注效果执行
- **EventManager**：作为协调器

代码量从 500+ 行减少到每个类 100-150 行，结构更清晰，更易维护和扩展。
